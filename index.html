Radar Tracking Simulator

A multi-target tracker written in C++20, running here in your browser. Most marks are false alarms. Make the sensor worse and see what the tracker keeps. All data is synthetic.

Conditions
Confirm a track after

Each scan runs the same five steps

  1. Predict. A Kalman filter moves every track forward and grows its uncertainty. That uncertainty is the ring around each track, drawn twenty times larger so you can see it.
  2. Gate. Mahalanobis distance decides which detections could belong to a track, measured in standard deviations rather than metres.
  3. Associate. The Hungarian algorithm pairs tracks and detections so total distance is smallest. Confirmed tracks choose first.
  4. Update. Matched tracks blend in their detection. Unmatched tracks coast on their prediction for a few scans.
  5. Manage. Leftover detections open tentative tracks. An M-of-N rule confirms the real ones, and repeated misses delete the rest.

What it measured

Five targets over 200 scans, 10 seeds per row, in the native build. One target turns and two cross at the same point. False alarms and false tracks are per scan, and error is position error.

The confirmation rule decides how the tracker behaves under clutter. Detection probability is the real limit: below about 60%, tracks drop and restart.

Where it stops

  • All data here is synthetic. It has never been tested on real radar data, and it models no real system.
  • A single constant velocity model lags sharp manoeuvres.
  • Global nearest neighbour cannot revise a decision it made in an earlier scan.
  • Timings came from one desktop core. Embedded hardware would differ.

How it was built

C++20 with Eigen, built with CMake on Linux. 61 tests run in release mode and under AddressSanitizer and UndefinedBehaviorSanitizer. The Hungarian solver is checked against exhaustive search. The tracker on this page is that same code compiled to WebAssembly, so nothing here is a mock-up.
